# swift-crypto 5.x Dependency Upgrade

**Status**: In Progress
**Plan ID**: PLAN-SC5-DEPS
**Depends On**: none (wave 1, runs in parallel with PLAN-SC5-VERSION)
**Design Reference**: `design-docs/specs/architecture.md#cryptography-dependency`

## Purpose

The owner wants every Swift package in the Riela dependency graph to require
apple/swift-crypto 5.x, so that Riela resolves a single 5.x version. In this
repository, `Package.swift` requires `from: "4.5.1"` and `Package.resolved`
pins swift-crypto 4.5.1 (revision `47d3869a7291f085c1fb9fb1e6d3b97a793f45c6`)
and swift-asn1 1.7.1. Move both to swift-crypto 5.x with no behavior change.

Repository context:

- `Package.swift:20` holds the swift-crypto requirement. `Package.swift:27`
  uses the `Crypto` product only on Linux:
  `.when(platforms: [.linux])`.
- The only crypto call is the PKCE S256 challenge, in
  `Sources/GoogleServiceGatewayCore/OAuthClient.swift:42`:
  `Data(SHA256.hash(data: Data(verifier.utf8))).base64URLEncodedString()`.
  Lines 1-5 import `CryptoKit` when available and `Crypto` otherwise.
- `Tests/GoogleServiceGatewayCoreTests/OAuthAndAPIKeysTests.swift:79` checks
  the challenge byte-for-byte, under `#if canImport(CryptoKit)`.
- The pinned `google-gateway-auth` dependency (revision
  `48e0112fb5eb057cf012194cfffaa2581ba29d76`) declares no swift-crypto or
  swift-asn1 dependency.
- `Package.swift` is the only package manifest; there are no nested ones.

## Non-Goals

- Changing `VERSION` or `Sources/GoogleServiceGatewayCore/Version.swift`.
  PLAN-SC5-VERSION owns those files.
- Changing the `google-gateway-auth` revision pin, swift-tools-version 6.0,
  `.macOS(.v14)` or `swiftLanguageModes: [.v6]`. If swift-crypto 5 requires
  one of these to change, stop and report it as a blocker. Do not edit it.
- Refactoring the PKCE code, replacing CryptoKit on Darwin, or changing the
  product condition.
- Updating any other dependency. Do not run a bare `swift package update`.
- Commit, push, release, or Homebrew work. The workflow finalizes these.

## Deliverables

- [ ] `Package.swift:20` reads exactly
      `.package(url: "https://github.com/apple/swift-crypto.git", from: "5.0.3")`.
- [ ] `Package.resolved` pins swift-crypto at 5.0.3 or a later 5.x. swift-asn1
      changes only if swift-crypto 5 requires it. `originHash` is regenerated by
      SwiftPM. No other pin changes.
- [ ] `Sources/GoogleServiceGatewayCore/OAuthClient.swift` stays unchanged
      unless swift-crypto 5 breaks the Linux `import Crypto` / `SHA256.hash`
      path. Any fix stays inside the existing `#if canImport(CryptoKit)`
      boundary and keeps the output byte-for-byte the same.

## Tasks

### TASK-001: Change the requirement and re-resolve

**Parallelizable**: Yes, with PLAN-SC5-VERSION. The two plans have no
overlapping files.

1. Read `Package.swift` and `Package.resolved` again, and record their
   `shasum -a 256` values in the Progress Log.
2. Edit only the lower bound in `Package.swift:20`: change `4.5.1` to `5.0.3`.
   Keep `from:`. Do not use `.upToNextMinor`, `exact:`, or a range.
3. Run `swift package update swift-crypto`. Use the targeted form only, so
   that other pins do not move.
4. Run `grep -n '"version"' .build/checkouts/swift-crypto/Package.swift` and
   `head -1 .build/checkouts/swift-crypto/Package.swift`. Inspect the checkout
   manifest's swift-tools-version, platforms, and swift-asn1 requirement, and
   record them in the Progress Log.
5. Run `git diff Package.resolved` and confirm that only the swift-crypto
   entry, the swift-asn1 entry (if needed), and `originHash` changed.

Pitfalls:

- If resolution fails with a version conflict, record the SwiftPM error text
  in the Progress Log and report it as a blocker. Do not add overrides, forks,
  or `exact:` pins. Do not change the google-gateway-auth revision.
- If the swift-crypto 5 manifest needs swift-tools-version above 6.0 or a
  platform minimum above macOS 14, do not edit `Package.swift` to match.
  Report it as a blocker.
- Do not hand-edit `Package.resolved`. Only SwiftPM writes it.
- Do not delete `.build` to "fix" resolution unless a stale checkout is the
  proven cause. If you delete it, record that in the Progress Log.
- Expect changes to files outside this plan's writePaths: PLAN-SC5-VERSION
  edits `VERSION` and `Version.swift` concurrently, and
  `design-docs/specs/architecture.md` already has an edit from earlier in
  the workflow. Never revert, restore, checkout or stash those files.

### TASK-002: Build and test with no behavior change

**Parallelizable**: No (after TASK-001)

0. Run `mkdir -p tmp`. `tmp/` is gitignored.
1. Run `swift build > tmp/sc5-build.log 2>&1; echo "exit=$?"` and record the
   printed exit code. Do not pipe into `tee`: without pipefail, `$?` is tee's
   status and hides a failure. Search the log for swift-crypto deprecation
   warnings that affect `OAuthClient.swift`.
2. Run `swift test > tmp/sc5-test.log 2>&1; echo "exit=$?"` and record the
   printed exit code.

   Scope note: PLAN-SC5-VERSION may edit `Version.swift` (and `VERSION`)
   during these runs. That is expected and does not affect the result. These
   build and test runs are plan-local evidence that the swift-crypto 5
   resolution compiles. The authoritative gates are the reconciliation runs
   of `swift build`, `swift test`, `mise run build`, `mise run test` and
   `mise run lint`. Do not run the mise gates in this plan.
3. If a Linux toolchain or container is available (`swift sdk list` shows a
   Linux SDK, or `docker` or `container` is present), run
   `swift build --swift-sdk <linux-sdk>` or a Linux container build. This is
   the only way to compile the `import Crypto` path. If none is available,
   record "Linux build not verified: no Linux toolchain" in the Progress Log.
   Do not install toolchains.
4. Only if step 1 or 3 reports an error or deprecation in the swift-crypto
   path: edit `OAuthClient.swift` minimally. Keep the computed bytes the same
   (SHA-256 digest, then base64url without padding). Do not touch the
   `CryptoKit` branch.
